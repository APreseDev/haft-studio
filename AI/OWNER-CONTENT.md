# چک‌لیست اطلاعات مورد نیاز از مالک سایت

همه‌ی متن‌های اصلی سایت در فایل `src/data.js` هستند. این فایل را با هر ویرایشگر متن باز کنید و فقط مقدارهای داخل گیومه را عوض کنید.

## ۱. نمونه‌کارها (ضروری قبل از انتشار)

در `projects` برای هر نمونه‌کار این‌ها را بنویسید:

- `title`: نام واقعی پروژه (تا وقتی داخل `[ ]` باشد، در سایت منتشرشده نمایش داده نمی‌شود)
- `tag`: دسته‌بندی
- `hint`: توضیح یک‌خطی (اختیاری)
- `image`: عکس نمونه‌کار. فایل را داخل `public/projects/` بگذارید و مسیرش را بنویسید، مثلاً `"projects/site-1.jpg"` (اختیاری)
- `alt`: توضیح عکس برای نابینایان (اختیاری)

اگر تا زمان انتشار هیچ نمونه‌کار واقعی ننوشته باشید، سایت جمله‌ی «نمونه‌کارها به‌زودی این‌جا اضافه می‌شود.» را نشان می‌دهد.

نکته: برای دیدن نمونه‌کارهای placeholder هنگام ویرایش، از `npm run dev` استفاده کنید.

## ۲. اطلاعات تماس

- تلفن، اینستاگرام و ایمیل فعلی تأیید شده‌اند و تنها راه‌های ارتباطی فعلی‌اند. اگر بعداً کانال دیگری اضافه شد، در `contact` (فایل `src/data.js`) و بخش تماس اضافه می‌شود.
- کلید Web3Forms عمومی است و پنهان‌کردنش لازم نیست (طبق مستندات رسمی فقط اجازه‌ی ارسال ایمیل به آدرس شما را می‌دهد). محدود کردن آن به دامنه یک قابلیت **پولی (Pro)** است و اختیاری؛ اگر اسپم زیاد شد، کپچای رایگان (hCaptcha) یا همان قابلیت را بررسی کنید.

## ۳. تیم

- نام و سمت دو عضو فعلی را تأیید کنید.
- برای نمایش حرفه‌ای‌تر، عکس رسمی‌تر و نزدیک‌تر از صورت بدهید و جایگزین `public/01.jpg` و `public/02.jpg` کنید.
- اگر عضو دیگری هست، به `team` اضافه کنید.

## ۴. اختیاری (فقط اگر واقعی دارید)

- نظر مشتریان (فقط با رضایت و نام واقعی)
- لوگوی تصویری (فعلاً طراحی نشده؛ سایت از نشان متنی «۷» استفاده می‌کند. بعد از طراحی لوگو، تصویر پیش‌نمایش لینک Open Graph هم ساخته می‌شود)
- صفحه‌ی حریم خصوصی، چون فرم نام و شماره تماس می‌گیرد
- نام حقوقی شرکت یا شماره‌ی ثبت، اگر می‌خواهید در فوتر باشد

## متن‌هایی که داخل کامپوننت‌ها هستند (نه `data.js`)

عنوان و توضیح هیرو (`src/sections/Hero.jsx`)، عنوان بخش‌ها (`Services.jsx`، `Process.jsx`، `Team.jsx`) و متن بخش تماس (`Contact.jsx`).

## ۵. سئو بعد از خرید دامنه

فقط یک کار: در `src/data.js` مقدار `siteUrl` را بنویسید (مثلاً `"https://example.com"`). بقیه (`canonical`، `og:url`، `sitemap.xml`، خط `Sitemap` در `robots.txt`) در بیلد خودکار ساخته می‌شود. بعدش سایت را در Google Search Console ثبت کنید.

اگر بعداً لوگو یا تصویر پیش‌نمایش آماده شد، نام فایل را در `ogImage` (همان فایل `data.js`) بنویسید.

## ۶. امنیت: کارهای دستی

- روی GitHub: احراز هویت دومرحله‌ای، فعال‌کردن Dependabot alerts و Secret scanning، و محافظت از شاخه‌ی `main` (در Settings).
- هدر `Content-Security-Policy-Report-Only` در `public/_headers` فعلاً فقط گزارش می‌دهد و چیزی را مسدود نمی‌کند. بعد از انتشار، سایت را در مرورگر باز کنید و در Console خطای CSP نبودنش را ببینید؛ اگر خطایی نبود، نام هدر را به `Content-Security-Policy` تغییر دهید.
- HSTS و «Always Use HTTPS» را بعد از اتصال دامنه در داشبورد Cloudflare فعال کنید (قبل از آن فعال نکنید، چون برگشتش سخت است).
- قبل از هر انتشار روی سیستم خودتان یک بار `npm audit` را اجرا کنید.

## ۷. GitHub و بیلد

**اولین بار (روی سیستم خودتان، داخل پوشه‌ی پروژه):**

```
npm ci
npm run build
npm run preview
```

اگر بیلد خطا داد، متن خطا را بفرستید. پوشه‌های `node_modules` و `dist` و فایل‌های `.env` در `.gitignore` هستند و روی GitHub نمی‌روند.

**ساخت مخزن:** شاخه‌ی اصلی باید `main` باشد (workflowها روی `main` تنظیم شده‌اند):

```
git init -b main
git add .
git commit -m "Initial commit"
```

**تنظیمات لازم در GitHub:**

- Settings → Actions → General: اجرای Actions فعال باشد.
- اگر با GitHub Pages منتشر می‌کنید: Settings → Pages → Source را روی **GitHub Actions** بگذارید.
- اگر با Cloudflare Pages منتشر می‌کنید، workflow به نام `Deploy to GitHub Pages` لازم نیست؛ در تب Actions آن را Disable کنید (فایلش را حذف نکردم).

**تنظیمات Cloudflare Pages (وقتی به مرحله‌اش رسیدیم):**

- Build command: `npm run build`
- Build output directory: `dist`
- نسخه‌ی Node از فایل `.nvmrc` (۲۲) خوانده می‌شود.
- متغیر `VITE_BASE` را تنظیم **نکنید** (پیش‌فرض `/` درست است).

**راهنمای کامل انتشار روی Cloudflare Pages و اتصال دامنه:** فایل `DEPLOYMENT.md`
