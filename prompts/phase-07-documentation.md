# Phase 7 — Project Documentation and PRD

Inspect the entire existing React project and create a comprehensive Markdown documentation file named:

`PROJECT_DOCUMENTATION.md`

The documentation must accurately reflect the actual project structure and implementation.

## Include

1. Project overview and purpose
2. Technologies and dependencies
3. Project architecture
4. Complete folder and file structure
5. Explanation of important files and folders
6. React components and their responsibilities
7. Component relationships
8. CSS and styling structure
9. Scroll animations and interactions
10. Background number 7 implementation
11. Cream section performance optimizations
12. Work Process section behavior
13. Logo implementation
14. Persian and English language system
15. RTL and LTR handling
16. Dark Mode implementation
17. Installation and setup instructions
18. Development and production commands
19. Build and deployment information
20. Maintenance and future development guidance
21. Known limitations and potential issues

## PRD Section

Include a structured Product Requirements Document covering:

- Product overview
- Product goals
- Target users, if identifiable from the project
- Functional requirements
- Non-functional requirements
- Performance requirements
- Responsive design requirements
- Accessibility requirements
- Language requirements
- Dark Mode requirements
- Acceptance criteria
- Project constraints
- Features outside the current scope

## Important

- Base all documentation on the actual source code.
- Do not invent files, features, dependencies, or functionality.
- Explain every relevant file and folder accurately.
- If something cannot be verified, explicitly state that.
- Keep the documentation clear and useful for future developers.
- Update existing documentation if appropriate rather than creating unnecessary duplicate files.

Create the Markdown file and briefly report its location and contents.

Do not make unnecessary changes to the website itself.
