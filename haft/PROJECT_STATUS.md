# وضعیت پروژه‌ی هفت استودیو

تاریخ آخرین به‌روزرسانی: ۲۰۲۶-۱۱-۰۴

## طبقه‌بندی نهایی: آماده با محدودیت‌ها (Production Ready with Limitations)

کد با bundler و مرورگر واقعی (Chromium) در حالت ساده‌شده تست شد و سالم بود. محدودیت‌ها: **بیلد واقعی Vite، لینت، و رفتار واقعی Three.js، GSAP و Lenis اجرا نشدند** (این پکیج‌ها در محیط کار نبودند)، و سایت هنوز منتشر نشده و دامنه‌ای وصل نیست. اولین بیلد واقعی در Cloudflare انجام می‌شود؛ اگر خطا داد، لاگ آن را بفرستید.

## وضعیت اولیه (قبل از کار)

- کد React/Vite سالم و منظم، با GSAP، Three.js، Lenis و فرم Web3Forms.
- `base: "/haft-studio/"` (مخصوص GitHub Pages، نامناسب برای Cloudflare و دامنه‌ی اختصاصی).
- `index.html` با زبان `en` و عنوان `haft-studio`، بدون description، Open Graph، robots، 404 و هدر امنیتی.
- ۴ نمونه‌کار placeholder در سایت عمومی (`[نام پروژه ...]`).
- workflow فقط برای GitHub Pages (بدون `environment: github-pages`).
- README قالب پیش‌فرض Vite. فایل‌های اضافه: `src/styles.zip` (کپی `styles.css`)، `public/icons.svg` (بدون استفاده)، پوشه‌ی `test/` (نسخه‌های قدیمی کد).
- مسیر عکس تیم دوشلاشه (`//`).

## تغییرهای مهم

- **انتشار:** `base` پیش‌فرض `/` (قابل تغییر با `VITE_BASE` برای GitHub Pages)، `.nvmrc`، `engines`، workflowهای `deploy.yml` (اصلاح‌شده) و `ci.yml` (جدید).
- **سئو و امنیت:** متادیتا، `robots.txt`، `404.html`، `_headers`، Dependabot، داده‌ی ساخت‌یافته‌ی Organization (فقط از اطلاعات خود مالک).
- **فرم:** اعتبارسنجی و نرمال‌سازی شماره (ارقام فارسی و عربی)، قفل ارسال تکراری، پیام‌های مشخص خطا و `maxLength`.
- **رابط:** تماس لینک‌دار، ستاره‌ی فیلد الزامی، حالت خطای فرم، اصلاح autofill، hover دکمه، عنوان‌های `h3` برای نمونه‌کارها.
- **محتوا:** نمونه‌کارهای placeholder در نسخه‌ی منتشرشده پنهان‌اند (در `npm run dev` دیده می‌شوند).
- **عملکرد:** سقف حدود ۶۰ فریم برای صحنه‌ی سه‌بعدی، افکت درخشش با import پویا فقط روی دستگاه‌های قوی، عدم دانلود صحنه‌ی سه‌بعدی با Save-Data، عکس‌های تیم از ۱۶۹ به ۵۶ کیلوبایت.

## تست‌ها و نتایج

**پاس‌شده (واقعاً اجرا شد):**
- ۲۳ تست واحد فرم و `api.js` (با fetch شبیه‌سازی‌شده)، شامل موفقیت، ۴۰۰، ۴۲۹، پاسخ غیر JSON، قطع شبکه، timeout و ۱۳ حالت شماره‌ی تلفن.
- `node --check` روی همه‌ی فایل‌های JS خالص.
- اعتبار JSON و YAML، توازن براکت‌ها در `src`.
- حل‌شدن همه‌ی importها (۲۶ فایل) و وجود همه‌ی عکس‌ها و فایل‌های ثابت و لینک‌های `#...`.
- اسکن اسرار: هیچ فایل `.env` یا کلید خصوصی نیست.
- lockfile: ۱۷۲ بسته همه از رجیستری رسمی npm و دارای integrity.

**پاس‌شده در مرورگر واقعی (Chromium headless، با شبیه‌ساز GSAP/Lenis/Three و فونت جایگزین):** ۴۷ بررسی روی عرض ۱۴۴۰، ۳۹۰ و ۳۲۰: بدون خطای Console و بدون فایل ۴۰۴، `lang=fa` و `dir=rtl`، یک `h1`، بدون اسکرول افقی، همه‌ی بخش‌ها و لینک‌های `#`، عکس‌های تیم، لینک‌های تلفن/ایمیل/اینستاگرام، پنهان‌بودن placeholderها، منوی موبایل (باز شدن و Escape)، صفحه‌ی ۴۰۴، و رفتار فرم (خطای نام و شماره با فوکوس، تبدیل ارقام فارسی، فقط یک ارسال با دوبار کلیک، پیام موفقیت، رد شدن سرور، قطع شبکه). یک بررسی «بارگذاری عکس» روی موبایل در نگاه اول رد شد؛ علتش `loading="lazy"` بود و بعد از اسکرول تأیید شد. همچنین کل کد با esbuild بدون خطا bundle شد (اثبات سالم‌بودن دستور زبان JSX و importها) و اسکریپت `postbuild` روی ۶ حالت (خالی، معتبر، تکراری، نامعتبر، نبودن dist) تست شد.

**اجرا نشد:**
`npm ci`، `npm run lint`، `vite build` واقعی، `npm audit`، رفتار واقعی Three.js (ظاهر و عملکرد صحنه)، GSAP (انیمیشن اسکرول)، Lenis، ارسال واقعی فرم و ایمیل، Lighthouse، Cloudflare.

**نیازمند تست دستی:** همه‌ی موارد بخش «اجرا نشد»، طبق `docs/QA-CHECKLIST.md`.

## مشکلات و محدودیت‌های شناخته‌شده

- بیلد و لینت هرگز اجرا نشده‌اند؛ ممکن است لینت خطا بدهد یا بیلد هشدار حجم chunk نشان دهد (تأییدنشده).
- سایت کاملاً سمت کاربر رندر می‌شود. گوگل جاوااسکریپت را اجرا می‌کند ولی ربات‌های ساده و پیش‌نمایش لینک فقط `head` و `noscript` را می‌بینند (پیش‌رندر انجام نشده).
- `canonical`، `og:url` و `sitemap.xml` خودکار ساخته می‌شوند، به شرط اینکه `siteUrl` در `src/data.js` پر شود (بعد از دامنه). `og:image` به لوگو نیاز دارد.
- فرم ایمیل کاربر را نمی‌گیرد؛ پاسخ فقط با تماس تلفنی ممکن است. پلن رایگان Web3Forms ۲۵۰ ارسال در ماه دارد و کپچا ندارد.
- CSP فقط در حالت Report-Only است.
- آستانه‌ی انیمیشن‌ها (موبایل یا دسکتاپ) با چرخش گوشی دوباره محاسبه نمی‌شود. `404.html` برای زیرمسیر GitHub Pages مناسب نیست (روی Cloudflare مشکلی ندارد).
- عکس‌های تیم غیررسمی‌اند. `@types/react` و `@types/react-dom` بدون استفاده‌اند (حذفشان به نصب با اینترنت نیاز دارد).
- افکت درخشش روی دستگاه‌های قوی ممکن است چند لحظه‌ی اول بعد از لود دیده نشود.
- رفتار Cloudflare (404، هدرها، دامنه‌ی `.ir`، دسترسی از ایران) فقط از مستندات تأیید شده، نه از آزمایش واقعی.

## بهبود کندی (انجام‌شده، تأییدنشده روی دستگاه واقعی)

کنترل‌کننده‌ی خودکار کیفیت صحنه‌ی سه‌بعدی (سبک‌تر یا ثابت‌شدن روی دستگاه کند)، حذف `mix-blend-mode` نشانگر ماوس و `backdrop-filter` منو، سقف رزولوشن ۱٫۲۵، و آدرس‌های عیب‌یابی `?noscene` و `?lite`. علت اصلی کندی روی دستگاه شما هنوز اندازه‌گیری نشده.

## Placeholderهای باقی‌مانده

- ۴ نمونه‌کار در `src/data.js` (در نسخه‌ی منتشرشده پنهان‌اند؛ جای آن‌ها عبارت «نمونه‌کارها به‌زودی این‌جا اضافه می‌شود.» نمایش داده می‌شود).
- `og:image` و `apple-touch-icon` (لوگو و آیکون PNG حالا گذاشته شده‌اند؛ نسخه‌ی SVG یا با وضوح بالاتر پیشنهاد می‌شود).

## کارهای مالک (به ترتیب؛ فقط کارهایی که به حساب‌های شما نیاز دارند)

1. نمونه‌کارها، و در صورت نیاز متن‌ها را در `src/data.js` با اطلاعات واقعی بنویسید.
2. ریپو را در GitHub بسازید و فایل‌ها را آپلود کنید (روش بدون دستور در `DEPLOYMENT.md`).
3. در Cloudflare: Workers & Pages ← Create ← Pages ← Connect to Git ← ریپو؛ Build command: `npm run build`، Output: `dist`.
4. دامنه را بخرید (پرداخت و احراز هویت با شماست) و طبق `DEPLOYMENT.md` وصل کنید.
5. `siteUrl` را در `src/data.js` پر کنید.
6. بعد از اولین انتشار: سایت را روی موبایل ببینید و یک فرم واقعی بفرستید (`docs/QA-CHECKLIST.md`)؛ هر چیزی که درست نبود را بفرستید.
7. اختیاری: عکس رسمی‌تر تیم، لوگو، کپچا برای فرم، صفحه‌ی حریم خصوصی.
